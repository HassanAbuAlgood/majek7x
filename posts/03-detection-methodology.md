# 7️⃣ منهجية الكشف — خطوات منظمة مش تخمين

> **الفرق بين الهاوي والمحترف**: الهاوي "بيجرّب وبيستنى". المحترف عنده **قائمة خطوات** بيعدّي عليها.

---

## 🔬 المنهجية في 8 خطوات

### الخطوة 1 — جهّز الحسابين
```
A = المهاجم (أنت، صلاحية منخفضة)
B = الضحية (حساب تاني تملكه أنت)
```
- سجّل حسابين بإيميلات مختلفة (استخدم `+` alias في Gmail: `me+a@`, `me+b@`)
- لو البرنامج بيمنع حسابات متعددة → استخدم حسابين في tenant مختلف بس مسموح
- خزّن التوكنز في ملف (مش في الـ report!)

### الخطوة 2 — ابنِ خريطة الكائنات

جدول زي ده لكل هدف:

| الكائن | endpoint | Method | مكان الـ ID | نوعه | حساسية البيانات |
|---|---|---|---|---|---|
| profile | `/api/v1/users/{id}` | GET/PATCH | path | UUID | عالية (PII) |
| invoice | `/api/v1/invoices/{id}` | GET | path | numeric | عالية (مالي) |
| team | `/api/v1/teams/{id}/members` | GET | path | UUID | عالية |

**الهدف**: 15-30 endpoint. من غير الخريطة إنت بتجرّب في الظلام.

### الخطوة 3 — ولّد بيانات حقيقية بـ B
- أنشئ طلب، فاتورة، ملف، تذكرة، دعوة فريق، مفتاح API…
- سجّل كل المعرّفات الناتجة

### الخطوة 4 — شغّل Autorize وتصفّح بـ B
```
1. Autorize → حط توكن A
2. اتصفّح التطبيق بحساب B (كل الصفحات، كل التابات)
3. Autorize هتعيد كل request بتوكن A
4. راجع النتايج: دور على 🔴 Bypassed
```
⚠️ على أهداف حقيقية: قصّر الـ scope واستخدم وتيرة هادية.

### الخطوة 5 — الفحص اليدوي للـ endpoints عالية القيمة

لكل endpoint في الخريطة، طبّق الأنماط من [[03-idor-deepdive/02-patterns-and-variants]]:

```http
# الأصل (B)
GET /api/v1/invoices/5001 HTTP/1.1
Authorization: Bearer <token_B>
→ 200 {"id":5001,"amount":1200,"client":"Acme Corp"}

# الاختبار (A على نفس الكائن)
GET /api/v1/invoices/5001 HTTP/1.1
Authorization: Bearer <token_A>
→ 200 {"id":5001,"amount":1200,"client":"Acme Corp"}   🔴 IDOR!
```

### الخطوة 6 — اقرأ الفروق بدقة (فن المقارنة)

استخدم `Burp → Comparer` (كليك يمين → `Send to Comparer`) وقارن **بالبايت**:

| الملاحظة | المعنى |
|---|---|
| نفس الرد بالظبط | ✅ IDOR مؤكد |
| فرق في الطول بس | غالبًا بيانات مختلفة → IDOR |
| `403` vs `404` | الكائن موجود بس ممنوع ← واصل البحث |
| `401` في الحالتين | فحص هوية شغال، مش فحص ملكية |
| رسالة خطأ مختلفة | oracle ← استخدمه |
| فرق في التوقيت | استعلام بيوصل للـ DB |

### الخطوة 7 — صعّد (Escalate)

لقيت read IDOR؟ متستسلمش عندها. اسأل:

```
┌─ هل أقدر أعدّل؟ → جرّب PATCH/PUT/DELETE
├─ هل أقدر أوصل لـ API keys أو secrets؟
├─ هل أقدر أغيّر الإيميل؟ → password reset → ATO = Critical
├─ هل أقدر أوصل لكل المستخدمين (تعداد)؟
└─ هل أقدر أبقى admin (mass assignment)؟
```

### الخطوة 8 — وثّق فورًا

**وثّق في لحظة الاكتشاف** — مش "بعدين". بعد ساعة هتنسى تفاصيل حاسمة.

## 🎯 أين تبحث أولًا؟ (ترتيب الأولويات)

رتب الـ endpoints بالترتيب ده:

| الأولوية | نوع الـ endpoint | ليه |
|---|---|---|
| 🔴 1 | أي endpoint فيه `/admin`, `/internal`, `/management` | BFLA + صلاحيات |
| 🔴 2 | الملفات والتنزيلات (`/download/{id}`, `/export/{id}`) | تسريب وثائق |
| 🔴 3 | المفاتيح والأسرار (`/api-keys/{id}`, `/webhooks/{id}`) | Critical محتمل |
| 🟠 4 | المالي (invoice, payment, transaction) | تأثير عالي |
| 🟠 5 | إدارة الفريق (`/teams/{id}/members`, `/invites/{id}`) | صلاحيات |
| 🟠 6 | الـ PII في الـ profile | واضح وسهل |
| 🟡 7 | الرسائل والتذاكر | متوسط |
| 🟡 8 | التحليلات والسجلات | أقل |

## 🧪 سيناريو تدريب كامل (طبّقه على crAPI أو Juice Shop)

```
1. سجّل حسابين: attacker@test.com و victim@test.com
2. بـ victim: أنشئ طلب + ارفع ملف + أنشئ تذكرة
3. سجّل المعرّفات: order=55, file=77, ticket=91
4. بـ attacker: جرّب
   GET /api/orders/55
   GET /api/files/77
   GET /api/tickets/91
5. لكل واحد طبّق الـ 16 نمط
6. وثّق أي فرق سلوكي حتى لو ماظهرتش بيانات
7. كرر على 20 endpoint
8. المخرج: تقرير تدريبي كامل كأنه حقيقي
```

## ⏱️ إدارة الوقت أثناء الصيد

| النشاط | الوقت الموصى به |
|---|---|
| الاستطلاع وخريطة الكائنات | 30% |
| اختبار الـ endpoints عالية الأولوية | 40% |
| محاولة التصعيد (escalation) | 20% |
| التوثيق وكتابة التقرير | 10% |

> ⚠️ **فخ المبتدئين**: يقضوا 90% وقت في الاستطلاع و10% في الاختبار.
> الاستطلاع وسيلة، الاختبار هو اللي بيجيب النتيجة.
> **قاعدة**: لو قضيت أكتر من 4 ساعات استطلاع على هدف واحد بدون أي اختبار → وقف وابتدِ اختبر.

## 📝日志 (سجل المحاولات)

اكتب في ملف لكل هدف:

```markdown
## target.com — 2024-XX-XX

### endpoint: GET /api/v1/invoices/{id}
- ID type: numeric متسلسل
- A على 5001: 403
- A على 999999: 404
- الاستنتاج: الكائن موجود، الفحص شغال
- جرّبت: PATCH → 405 | POST → 403 | Content-Type xml → 403
- النتيجة: ❌ مفيش IDOR (حتى الآن)

### endpoint: GET /api/v1/teams/{id}/members
- A على team بتاع B: 200 ✅ بيانات الأعضاء
- 🔴 IDOR مؤكد
- التصعيد: جرّب POST invite بـ role=admin → ?
```

السجل ده **أهم أصل عندك**. بيمنعك من تكرار نفس الفحص، وبيوريك أنماط الهدف.
